Windows 10/11 with winget. Click Yes on the permission prompts for nvm and Node. Read the script first

What it does

  1. nvm + Node.js 24 LTSNode Version Manager, so the workshop's Node version doesn't touch your other projects.
  2. Python 3.10+Keeps the Python you have if it's new enough. Otherwise installs Python 3.12 (uv on macOS/Linux, winget on Windows).
  3. The workshop repoClones it into ~/devfest-mangaluru-2026-voicebot and runs a single npm install for all five phases.
  4. Phase 05 Python packagesPre-installs the tools service's packages into a .venv, so phase 05 works offline too.
You can run it again any time: steps that are already done get skipped. When it says All set, open a new terminal window so it picks up nvm.

Check it worked

cd ~/devfest-mangaluru-2026-voicebot/phase-01 npm run dev

Open http://localhost:3000, click Start listening, allow the microphone and say something: the speech meter should move. The Spark services in the header stay red until you're on the workshop network. That's expected at home.

If something goes wrong

macOS: “xcode-select: note: install requested…”

git needs Apple's Command Line Tools. Finish the installer window that opened, then run the command again.

nvm: command not found / node: command not found

Your current terminal started before nvm was installed. Open a new terminal window. If that doesn't help, run:

source ~/.nvm/nvm.sh && nvm use 24
Windows: “running scripts is disabled on this system”

The script fixes this for your user. If your company laptop blocks it, use npm.cmd instead of npm, e.g. npm.cmd run dev.

Windows: nvm use fails or Node still shows an old version

An older Node.js installed from nodejs.org gets in nvm's way. Uninstall “Node.js” from Settings → Apps, then run the command again.
